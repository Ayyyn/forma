# Muse design tools

In Studio, choose **Design with tools** beside the prompt composer. **Quick edit** retains the shorter feature-planner path for ordinary edits. Both create reviewable proposals; neither automatically changes the saved project. The API equivalent is `POST /api/studio/agent` with `agent_mode: "tools"` and the existing document ID/prompt fields.

Design mode uses one Muse conversation with bounded tool calls. It first records alternatives, assumptions and an implementation strategy, then inspects/builds trial candidates, obtains actual tool feedback and can revise them. It has access to native feature references, project/topology inspection, body measurements, targeted construction, solid interference, prescribed general mechanism paths, supported folding studies, four CAD review views and checked exports. Tool errors and trial sources are retained locally, including unsuccessful runs.

## Scope of verification

A selected design is a **geometry proposal for review**, not certification that the mechanism works physically. Selection requires valid native geometry, a passing independent-body interference check, STEP/STL read-back checks and image delivery followed by a written visual review. A motion check that was run must also pass. Assumptions, alternatives and unresolved work appear in the proposal review. Geometric qualification is tied to the source and tool versions; later changes mark it stale.

General motion accepts model-declared root-first fixed/revolute/prismatic trees on actual native solids, named configurations and optional point/axis loop constraints. It checks all body pairs at sampled poses. The declared joints are virtual: manufactured guides, engagement, locks, floor usability, strength, friction, fatigue and continuous swept volumes require additional evidence. A valid path does not satisfy those requirements automatically. General mechanism source is retained in portable JSON and can be rerun in Motion; playback reports path progress rather than a fictitious common hinge angle.

`check_motion` accepts `spec: {}` when the candidate already declares `metadata.design_mechanism`. It resolves that exact current definition before cache lookup and validation; a missing mechanism is rejected. This shorthand does not infer hardware or reuse an earlier candidate's motion definition.

`check_floor` measures horizontal native support projected over an explicit rectangular target and Z band, including actual holes and seams. It reports missing area and support heights. Rectangular faces are exact; curved outlines use native tessellation with a reported approximation. Coverage does not prove flatness, liquid tightness, wall attachment or load capacity. A multi-size floor study requires coverage checks and actual `render_state` images for every declared size, using the same mechanism definition as the sampled motion. Named-state renders report exact native outer bounds; inspecting only the construction pose can miss large protrusions in a smaller configuration. Motion offers direct buttons for those states, and Properties retains the checked floor targets with current/stale status.

`probe_translation` releases the virtual constraints and attempts a sampled rigid translation of selected bodies against the remaining solids. It reports the first sampled obstruction and its native intersection bounds. Probe axes are world coordinates, and optional named states use the actual posed source solids. This can reveal a missing guide or an escape direction. An obstruction proves only that local sampled translation is blocked; global captivity, rotation, positive locks, assembly and strength remain separate requirements.

`probe_prismatic_pair` batches both axial signs and four orthogonal transverse directions for one actual parent/child interface. Directions follow the parent's current rotation. It excludes other components so an unrelated floor cannot masquerade as a guide. Use it alongside whole-assembly motion/interference; existing interface walls can also obstruct probes without proving manufactured guidance or print fit.

`check_assembly` starts every printed body separately and checks an explicit staged installation into the source pose or a named mechanism state. It supports translations and world-origin rotations, adaptive finite sampling, 2–24 bodies and up to 20 stages. A retained assembly plan must pass again on a changed candidate. It does not infer a feasible path, hand access, gravity support or elastic snap assembly. Saved plans can be played with **Run assembly study** in Motion.

`check_retention` releases virtual constraints and checks requested parts in all six world directions at named operating states. `check_prismatic_controls` compares actual locked obstruction with legal unlocked travel and physical end stops, moving the complete descendant group of a single or coupled prismatic mode. Explicit retained limits and matched positions prevent a candidate from passing by changing its virtual travel declaration. Both tools can read exact acceptance targets from `metadata.native_study_targets` using `spec: {}`. When those targets exist, selection, native recheck and mechanical print release require fresh passing reports for the current candidate and motion definition. Local translation controls do not prove global or rotational captivity, friction, forces or physical fit.

For repeated named-state diagnostics, `mechanism_spec: {}` refers to this exact candidate's latest recorded `check_motion` spec. Resolution occurs before cache lookup, so changing the recorded motion cannot reuse old probe results. New candidates and changed imported assets require a fresh motion check. Original and resolved arguments are retained; explicit full specs remain available.

Lock diagnostics need matched locked and unlocked controls on the same physically moving group. A jam or another corner's obstruction can look like a lock. Check coordinated adjustment modes where the mechanism requires parts to move together. Sampled native obstruction does not measure friction, hand force or strength.

No general force solver, arbitrary sketch constraint solver, autonomous novelty assessment, unrestricted code execution or reference-browser tool is implemented in this mode. Unsupported work remains explicit rather than being silently replaced by a folding template.

## Editable rigid components

Primitive additions/cuts and holes accept an optional `target_part_id` to modify one existing body. Without it, legacy global behavior is preserved. Union accepts optional `part_ids` to join selected bodies while preserving others. Body ordinals can change after these operations; inspect the returned geometry before choosing subsequent targets. A disconnected union can still produce multiple solids and does not establish a physical joint. Target bodies and union selections are editable in Properties.

## Runtime and cost

The loop limits model turns, tools per turn, candidates and motion samples. Exact tool results and native builds are reused within their actual source/asset identities. A failed HTTP 429/502/503/504 can receive one retry; ambiguous timeouts are not retried automatically. Empty actionable output is never forwarded as an invalid assistant message; one bounded larger-output retry is permitted before an explicit incomplete result. The existing shared application budget guard and receipts apply to every request and retry. Estimates, reservations and actual provider billing remain different quantities.

Repeated general motion studies reuse complete native reports only for the same owned native build, asset bytes, source geometry and validated mechanism/sampling definition. Copies prevent caller mutations, failed studies remain failed, simultaneous duplicates share work and the process-local cache has entry/serialized-size limits. Direct independent builds bypass reuse. No motion samples or acceptance checks are omitted on an initial or changed study. Startup loads a requested revision once, and history refresh requests only document summaries. Imported drawing projection identity also includes asset bytes.

Failed STL checks include bounded edge-incidence diagnostics with coordinates and the actual affected component's read-back result. Separate component diagnostics remain available when an assembled mesh fails. No automatic mesh repair or relaxed acceptance occurs; component success cannot bypass an assembled-export failure at selection.

For a retained named-state floor study, Properties → **Recheck native study** reruns the existing floor targets, whole sampled motion, source interference and strict exports without a model call. It saves a new revision with source/tool/asset/target-bound numeric evidence. Changed geometry or targets makes it stale; failures remain failures. This does not regenerate a design, replace the earlier model's visual assessment, change requirements, or verify physical locks/strength/print fit. It provides an inexpensive way to revalidate human revisions without asking the model to repeat numerical work.

Newly named states can retain explicit footprints in `metadata.native_study_targets.states`, with separate origin/author metadata. Every declared motion state needs a target. This keeps human/native targets separate from an earlier model review; missing targets fail and changing a target invalidates numeric evidence.

Motion → **Download video** records the complete checked path forward and back as a local 1280 × 720 WebM, with source revision, dimensions and scope visible in the video. No model call or upload is used. The export can be cancelled; a revision/settings change discards it. Browser canvas recording support is required. The video shows prescribed native poses; contact friction, forces, print fit and physical lock qualification remain separate. Diagnostic videos of failed studies are labelled as having geometry issues.

An incomplete run with retained tool actions offers **Continue design**. It requires the same original project, instruction and selection. The checkpoint replays prior native tool actions locally under current code/assets, supplies current CAD, floor-diagnostic and named-state images where present, and resumes the model conversation. Replayed actions carry zero new provider charge and retain their source run/response provenance; new responses are counted separately. Changed sources require a new proposal. This is checkpoint continuation, not a fresh design or automatic physical approval; completed projects and budgets are never reset.

Portable source retains the design review and model-response provenance. The export workflow report explicitly marks a review current or stale, and includes a declared general mechanism study when configured. Review identity accounts for source, imported bytes, tool/package versions and font; numeric browser serialization and expanded folding defaults alone do not invalidate it.

For independent components, Export → **Separate body meshes** supplies one STL per native body and a manifest with native-bound/volume and mesh read-back checks. It preserves touching components as separate files. The assembled STL is a geometric union and can fuse movable interfaces. Component coordinates are preserved for reassembly; arrange and orient them in a slicer. This generic package does not establish a printer-specific layout, supports, fit or print readiness. Supported folding assemblies retain their separate oriented print-pack workflow.

This mode adds more inspections than Quick edit and has not established a general speed or quality advantage on a held-out benchmark. Experimental reasoning policies are explicit and do not change production defaults automatically.

Studio bounds a design batch to 20 model turns and 16 tool calls per response. Continuations report local tool revalidation separately from new model reasoning. Exact owned native trajectories reuse bounded process-local reports with defensive copies; changed geometry, assets, sampling, targets or mechanism definitions require new work.

The Studio tools profile starts with a 16,384-token response allowance and permits one bounded output-limit retry up to 32,768 tokens. Programmatic callers can select a smaller explicit policy; changing that policy is not a new model or a benchmark improvement by itself.

The tool planner supplies editable geometry, constraints and targets in full, references exact duplicate source documents, and indexes historical native reports instead of repeating their complete payloads. `inspect_retained_report` retrieves an exact original report on request; it cannot promote old evidence. Full source context remains local for strict checkpoint validation, separately from the transmitted request receipt. New checks, failure diagnostics and acceptance gates remain explicit. Response deadlines are bounded to 600 seconds for the largest profile.

`check_handling` tests retained unwanted staged translations from named states with virtual constraints released. Joint descendants move together; an initially intersecting pose cannot count as capture. Finish, native recheck and print release require the exact retained paths to meet a positive-offset obstruction. These controls cover their stated paths, not global captivity or physical forces. Additional verified keeper parts/states can strengthen retention coverage; the original distance, samples and coverage remain mandatory, and the stronger contract persists on selection.

Installation diagnostics stop at the first collision and label the tested prefix and full planned sample count. Every passing installation still checks every planned pose. Original complete failed reports remain historical evidence rather than being regraded as partial runs.

Offline regression: `research/vendor/cad-runtime/Scripts/python.exe -m research.run_forma_checks`. The manifest covers Forma and excludes the separately scoped earlier research apps. Paid development checks use `research.verify_design_agent` only with an explicit `--run-paid` flag; original failures, source snapshots and continuation provenance remain local.

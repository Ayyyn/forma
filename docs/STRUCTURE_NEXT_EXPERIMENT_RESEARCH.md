# Structure research: 3D, perception, agents and data

Research note, October 29, 2026. Recommendations, not implemented capabilities or new benchmark results. Frozen structural pilots remain unchanged. No paid inference was performed for this note.

## What the simple experiment establishes

The current nine-node planar frame problem is a verification fixture and a development benchmark. It tests beam mechanics, tool integration, budget accounting and candidate replay. It does not establish that a model can discover useful structures across arbitrary physics. Its initial apparent Meta gains disappeared against a broader conventional catalogue in two diagnostic cases. Increasing dimension alone does not establish AI value.

The next useful hypothesis is whether a model helps translate requirements, identify useful structural concepts and repair designs after a change, while numerical tools handle sizing. These responsibilities were largely supplied by us in the first pilot. End-to-end workflow utility and search quality conditional on a correct formulation must be scored separately.

## Recommended next mechanical scope

Use a bounded **3D compliant instrument mount/stage** research task: allow small translation in one specified direction, resist orthogonal translations and unwanted rotations, route members around a reserved cable/tool corridor, and minimize material under several loads. Include changes to corridor position or material modulus after the initial design. This is relevant to instrumentation and potentially device housings; it is not an implant or clinical performance model.

Use a true spatial beam/frame adapter, with translations and rotations at each node, axial deformation, bending in two planes and torsion. A pin-jointed axial truss is a different model and must not be presented as a flexure simulator. Define circular/other explicit section properties and local-axis conventions. Check actual member envelopes and segment distances for finite-radius collisions. Rigid ideal joints and small displacement still limit interpretation; cross-check selected designs with a finer beam discretization or suitable solid model where feasible.

Before inverse design: reproduce analytical axial/bending/torsion cases, energy and reaction balance, rigid-coordinate covariance, and a published spatial reference case. Frame3DD publishes pyramid, tetrahedral and lateral-torsional examples with input/output files. It is GPL software; using it as an independent external reference and incorporating its code are different decisions. No Frame3DD code was downloaded or incorporated in this research step. [Frame3DD](https://frame3dd.sourceforge.net/)

Do not combine finite-mount boundary conditions and periodic-lattice homogenization. A periodic stiffness tensor does not certify a finite device with clamps and joints. Likewise, a linear frame model cannot certify large-stroke motion, snap-through, fatigue or tissue interaction.

## AI system choices

1. Preserve the broad numerical generator and constrained sizing optimizer as a serious control. Add multi-start/mutation as appropriate. Use the same admissible geometry and physics in every arm.
2. Compare Muse Wonder with the current Muse Spark Open on a small separate development set using the same tools, candidate and token/cost limits. Official API listings include Wonder; its advertised coding/agent strengths are a reason to test, not evidence of mechanical competence. The earlier local preflight received Wonder HTTP 200 and `API_OK` on October 27; that was an access check, not a design benchmark. [Meta API catalogue](https://dev.meta.ai/products/meta-model-api)
3. Supply exact nodes, sections, loads, supports, units, constraint violations and sensitivities. Add deterministic multiple-view geometry and deformation renders with labeled axes and explicitly declared deformation magnification. Test image context against the same controller with structured data only. The previous pilot already transmitted geometry images; their causal benefit was not isolated.
4. Retain an evidence ledger: candidate identity, assumptions, changes, actual tool returns, failure classification, resource consumption and verified acceptance. Let the controller propose structured edits and request tests; never let it approve its own mechanics.
5. Only after a working single-controller comparison, test an optional proposer/reviewer split. Reviewers should check assumptions and search for counterexamples, not vote that a structure looks plausible. They share one total inference and simulation budget; compare against one controller with the same resources and against equally diverse numerical starts. Multiple model opinions are not independent physical verification.
6. Defer training an RL policy. Solver feedback alone is not RL training. Sparse feasible rewards, a changing design language and insufficient unseen evaluation create extra failure modes. Bayesian optimization and active learning are appropriate controls for an expensive/noisy experiment-selection task; gradients/local optimization remain strong for cheap differentiable sizing.

The official [Muse Spark Open page](https://dev.meta.ai/models/muse-spark-open) describes native image/video/document perception. A separate vision model is therefore not required merely to inspect numerical renders. [SAM 3.1](https://dev.meta.ai/models/sam-3-1) is useful for segmentation/tracking if photographs or test video become inputs. A mask alone supplies neither physical scale nor hidden 3D geometry, material parameters or calibrated displacement. The earlier SAM fixture preflight checked a synthetic box and mask presence, not metrology or tracking accuracy. [Muse Image](https://dev.meta.ai/models/muse-image) may assist visual ideation, but generated pixels are not an engineering model. Voice transcription is optional interface work, not a current scientific bottleneck. There is no need to deploy every eligible model.

## Dataset shortlist

**First 3D candidate: Cambridge linear elastic strut-lattice dataset.** The repository describes lattice geometry and compliance tensors at different relative densities, computed with ABAQUS, with reproduction scripts. The record lists CC BY 4.0 and roughly 123 MB category archives. Associated lattice-processing and energy-equivariant GNN repositories are available. Use a small attributed subset for reference/retrieval or offline design selection; verify conventions, boundary conditions and units first. Metadata/repositories were inspected; data files and reference solver outputs have not been downloaded or reproduced. These are simulated properties, not measured prototype outcomes. [Dataset](https://doi.org/10.17863/CAM.106854), [processing library](https://github.com/igrega348/lattices), [GNN research code](https://github.com/igrega348/energy-equiv-lattice-gnn).

**Best match to retrospective experiment selection: Boston University KABlab.** The lab links crossed-barrel measurements and a version augmented by FEA, and reports 821 quasi-static and 247 impact lattice tests. Its quasi-static page links raw force-distance traces, movies and metadata. This could support a masked-label replay: choose the next measured design, reveal only its archived outcome, and compare against random/space-filling selection and Bayesian optimization. Audit candidate features, repeated tests, material/print settings, adaptive collection bias and terms before use. No files have been audited or ingested; some BU repository pages returned HTTP 403 to the web reader. Replaying historical tests measures retrospective query efficiency, not newly avoided prototypes. This is established autonomous mechanical-design research and must be attributed. [Lab data index](https://www.kablab.org/data), [quasi-static data description](https://www.kablab.org/lattice-quasi-static).

**External experimental check: Bath curved-link auxetic structures.** The record supplies tests for 19 structures, FE inputs/results, CAD and tracking analysis. The archive is about 1 GB under CC BY 4.0, with ANSYS/Inventor/MATLAB dependencies for full original workflows. Useful for matching one explicit published specimen or checking simulation/measurement mismatch; too small to assume it trains a broadly generalizing model. Metadata only inspected. [Dataset](https://researchdata.bath.ac.uk/1525/).

**Alternatives if scope changes.** [SELTO](https://zenodo.org/records/7781392) contains voxelized 3D topology-optimization problems/solutions with material data, supports, forces and design regions, suitable for solid topology work rather than direct beam reuse. [TopoDiff](https://decode.mit.edu/projects/topodiff/) supplies 33,000 2D topology images with physical fields and constraints; useful as prior art/reference, not proof of 3D performance. [Mechanical MNIST](https://elejeune11.github.io/) focuses on forward mechanics from heterogeneous material bitmaps. [MIT's LINKS listing](https://decode.mit.edu/projects/eng-datasets/) describes planar linkage kinematics; use it if following a motion path becomes the task, without mistaking kinematic feasibility for load-bearing mechanics. Public availability does not remove per-artifact attribution/license checks.

## Data and evaluation requirements

A pretrained Meta tool controller needs no newly trained large dataset. We do need credible reference mechanics, representative requirements and untouched evaluation cases. A learned surrogate or trained RL policy additionally needs a training set and its own extrapolation/error checks. Retrieval examples must be available to a corresponding retrieval-plus-numerical control so model gains are not just privileged data access.

Choose either spatial-frame inverse design or retrospective measured-lattice selection as the next primary study; do not spread the remaining time across all datasets. The first is the more direct continuation of the current architecture and motion preference. The second is the more direct test of experimental query efficiency if usable data can be audited quickly.

For a fresh prospective benchmark, freeze the broader numerical generator, model/tool interface and unseen case generator before revealing scores. Report verified completion, paired objective gaps, actual solver work, inference tokens/cost and latency separately. Include image/no-image and model comparisons sequentially; add agent splitting only if a specific observed failure justifies it. Score requirement extraction and revision preservation explicitly. Complex geometry, more agents or a larger model are hypotheses to test, not promised performance improvements or a novelty claim.
